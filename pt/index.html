Trabalho em destaque

  • MediaTrack

    Aplicação full-stack para registar filmes, séries, anime, manga e livros, com uma só pesquisa em TMDB, AniList e Open Library. Início de sessão sem palavra-passe, isolamento de dados por utilizador com Row Level Security e builds nativos para iOS e Android a partir do mesmo código.

    Next.jsTypeScriptSupabaseTailwindCapacitorGitHub Actions
    Ver código no GitHubExecuções de CI
    Como funciona
    • Um único build corre na web, como PWA e dentro do Capacitor em iOS e Android. Uma barreira de autenticação no cliente substituiu o middleware de servidor que o export estático não consegue usar.
    • O início de sessão é sem palavra-passe, com um código de uso único por email. No telemóvel, a sessão fica guardada no Keychain ou no Keystore.
    • O Row Level Security mantém a biblioteca e as avaliações de cada utilizador privadas, garantido no PostgreSQL e não no código da aplicação.
    • A pesquisa chama TMDB, AniList e Open Library em paralelo e tolera uma fonte a falhar, e depois normaliza tudo num só modelo.
    • A biblioteca fica em cache para leitura offline, e os lembretes são agendados localmente no dispositivo.
    • O GitHub Actions constrói a aplicação a cada push, evita que o projeto Supabase gratuito seja pausado e pode enviar builds iOS para o TestFlight.

    Limitações e próximos passos

    • Os pedidos aos catálogos saem diretamente do cliente, por isso o token de leitura do TMDB vai no bundle e os limites de pedidos são por dispositivo. Um pequeno proxy com cache resolveria as duas coisas.
    • Ainda não há testes automatizados. A normalização da pesquisa é a primeira coisa que eu cobriria.
    • O modo offline é só de leitura: as alterações precisam de ligação, porque escrevem no Supabase.

  • spring-boot-auth-template

    Um starter Spring Boot reutilizável para autenticação JWT e gestão de utilizadores com controlo de acesso por papéis. O registo cria sempre um utilizador normal, os administradores gerem todos e cada utilizador gere apenas a sua conta. Coberto por testes automatizados e CI.

    Java 17Spring Boot 3Spring SecurityJPAJWTPostgreSQLFlywayDockerJUnit 5GitHub Actions
    Ver código no GitHubExecuções de CI
    Como funciona
    • Sessões sem estado: cada pedido leva um JWT assinado (HS256). A chave de assinatura vem da variável de ambiente JWT_SECRET, por isso nenhum segredo fica no repositório.
    • Os papéis são aplicados com segurança ao nível do método. O registo cria sempre um USER, por isso um cliente nunca pode escolher o próprio papel. Os administradores gerem todos, e os utilizadores gerem apenas a sua conta.
    • As palavras-passe são guardadas com hash BCrypt. Um registo de auditoria de segurança regista logins (com sucesso e falhados), registos, remoções e acessos negados.
    • Os erros devolvem um formato JSON consistente através de um tratador global de exceções.
    • O Swagger UI e a consola H2 só estão ativos no perfil dev. Em produção a aplicação corre em PostgreSQL com migrações Flyway, e docker compose up arranca toda a stack.
    • Testes unitários e de integração, incluindo registo concorrente.

    Limitações e próximos passos

    • Os tokens de acesso duram 24 horas e não podem ser revogados antes de expirar. Próximo passo: tokens de acesso de curta duração com rotação de refresh tokens e uma lista de revogação.
    • Não há limite de pedidos nem bloqueio de conta no login, por isso a proteção contra força bruta fica para um gateway ou um futuro filtro.
    • Os registos de auditoria vão para ficheiros de log. Em produção devem ser enviados para um armazenamento central, por exemplo através da configuração Logstash incluída.
    • Existe apenas uma tabela. Um serviço real acrescentaria verificação de email e recuperação de palavra-passe, e testes contra um PostgreSQL real com Testcontainers.
