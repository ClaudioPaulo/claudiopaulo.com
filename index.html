Selected work

  • MediaTrack

    Full-stack app to track movies, series, anime, manga and books, with one search across TMDB, AniList and Open Library. Passwordless sign-in, per-user data isolation with Row Level Security, and native iOS and Android builds from the same code.

    Next.jsTypeScriptSupabaseTailwindCapacitorGitHub Actions
    View code on GitHubCI runs
    How it works
    • One static build runs on the web, as a PWA, and inside Capacitor on iOS and Android. A client-side auth gate replaced the server middleware that static export cannot use.
    • Sign-in is passwordless with an email one-time code. On the phone the session is kept in the Keychain or Keystore.
    • Row Level Security keeps each user's library and reviews private, enforced in PostgreSQL rather than in app code.
    • Search calls TMDB, AniList and Open Library in parallel and tolerates a failing source, then normalizes everything into one model.
    • The library is cached for offline reading, and reminders are scheduled locally on the device.
    • GitHub Actions builds the app on every push, keeps the free Supabase project from pausing, and can upload iOS builds to TestFlight.

    Limitations and next steps

    • Catalogue requests come straight from the client, so the TMDB read token ships in the bundle and rate limits are per device. A small caching proxy would fix both.
    • There are no automated tests yet. The search normalization is the first thing I would cover.
    • Offline mode is read-only: changes still need a connection because they write to Supabase.

  • spring-boot-auth-template

    A reusable Spring Boot starter for JWT authentication and role-based user management. Registration always creates a regular user, admins manage everyone, and each user manages only their own account. Covered by automated tests and CI.

    Java 17Spring Boot 3Spring SecurityJPAJWTPostgreSQLFlywayDockerJUnit 5GitHub Actions
    View code on GitHubCI runs
    How it works
    • Stateless sessions: every request carries a signed JWT (HS256). The signing key comes from the JWT_SECRET environment variable, so no secret lives in the repository.
    • Roles are enforced with method security. Registration always creates a USER, so a client can never choose its own role. Admins manage everyone, and users manage only their own account.
    • Passwords are hashed with BCrypt. A security audit logger records logins (successful and failed), registrations, deletions and denied access.
    • Errors return a consistent JSON shape through a global exception handler.
    • Swagger UI and the H2 console are only enabled in the dev profile. In production the app runs on PostgreSQL with Flyway migrations, and docker compose up starts the whole stack.
    • Unit and integration tests, including concurrent registration.

    Limitations and next steps

    • Access tokens last 24 hours and cannot be revoked before they expire. Next step: short-lived access tokens with refresh-token rotation and a revocation list.
    • There is no rate limiting or account lockout on login, so brute-force protection is left to a gateway or a future filter.
    • Audit entries go to log files. In production they should be shipped to a central store, for example through the included Logstash config.
    • Only one table exists. A real service would add email verification and password reset, and tests against a real PostgreSQL with Testcontainers.
